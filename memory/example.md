## 記憶系統的設計
```
                    ┌─ 第 1 層：本局短期記憶（回扣用）
  deep 路徑觸發 ──→ │    state["said_so_far"] — update_memory 在每個非 routine 步
                    │    寫入「#手數 棋步: 事件 (評估)」，檢索時取最近 3 條當回扣素材
                    │
                    ├─ 第 2 層：長期棋理（ChromaDB 向量檢索）★ 這次做的
                    │    語料：memory/theory_seed.py 約 30 條
                    │    查詢：事件詞彙 → embedding 比對 → 撈 2 條
                    │
                    └─ 第 3 層：棋手風格檔（未做，spec 的 stretch）
                              ↓
              兩層結果填進 FactsPacket.memory → analyst 的 prompt
```

三個關鍵設計決定：

1.雙語語料：embedding 模型（MiniLM）中文很弱，所以每條棋理存兩份——英文關鍵字拿去做向量比對（因為管線的事件詞彙 sacrifice、fork 本來就是英文），中文正文給 analyst 引用。
2.查詢字串不是 FEN，而是把當下時刻翻譯成事件語言：事件類型 + motif + 階段 + 棋子 + 落點格，開局時再附上前 8 步 SAN（讓具名開局能命中）。
3.離線契約：沒裝 chromadb 或模型下載失敗，自動退回關鍵字重疊計分，管線不會死。
